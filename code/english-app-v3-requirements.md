## 需求 1：按住说话 Bug + 微信式语音动画

### 1a. Bug 排查清单（P0，先修 Bug 再换动画——不在未定位的组件上叠加交互重构）

现有实现（NceRepeatScreen.kt 底部操作区）：`detectTapGestures(onPress)` → `asrEngine.startListening()` → `awaitRelease()` → `stopListening()`；`isListening` 是局部 `remember` 状态；录音中仅在按钮内显示 `WaveBarsIndicator`。按这个实现，用户四类症状的嫌疑点：

| 用户症状 | 代码嫌疑点 |
|---------|-----------|
| **按下无反应** | ①`repeatEnabled=false`（PLAYING 阶段）时 `pointerInput` 直接 return，按钮灰但**无任何"请先听原声"提示**，用户当 Bug；②`asrEngine.startListening()` 的失败（权限未授/引擎忙/麦克风被占）无独立错误路径，按下后既无动画也无 hint |
| **动画不出现** | `isListening` 置 true 在 `startListening()` 之后同步执行，理论应出现；若不出现 → 疑似 `pointerInput(repeatEnabled)` 在 phase 切换瞬间重建手势导致 onPress 未触发，或主线程被 ASR 启动阻塞 |
| **松手不识别** | ①极短按（<300ms）无防误触：start→stop 立即发生，ASR 来不及出 Final，`AsrEvent.Error`/空结果只显示一行 hint 且**在可滚动区里，易被顶走看不见**；②手指滑出按钮范围松手——`detectTapGestures` 的 `awaitRelease()` 不区分位置，照常 stopListening 发送（也可能反过来：用户以为松手在按钮上，实际已滑出）；③全局 `asrEngine.events` 流被 Chat 页和 Nce 页同时 collect，若前一页未释放，Final 事件可能被别的消费者截走 |
| **崩溃/卡死** | `awaitRelease()` 在系统打断（来电/通知抢焦点）时不结束 → `isListening` 卡 true、`stopListening()` 永不调用 → 永久录音态；另外 `onDispose` 只停了 `nceAudioPlayer`，**没停 asrEngine** |

**修复纪律**：以上逐条验证并修复后，才进入 1b 动画升级（否则换完动画找不到原 Bug）。修复验收标准：三页各连按/快按/滑出/来电打断各测 10 次，无卡死、无静默失败。

### 1b. 微信式交互状态机（P1，1.5~2 天，抽通用组件三页接入）

> 视觉口径（用户拍板，v2 修订）：不用"悬浮气泡"，采用**微信新版底部圆顶**——按下后屏幕底部升起全屏宽绿色大圆顶（约 1/5 屏高、弹性升起），中央白色麦克风图标，圆顶上方一行提示文字，背景压暗。下表"表现"列均按此口径。

| 状态 | 触发 | 表现 |
|------|------|------|
| 空闲 | — | 底部胶囊按钮【按住 跟读】原样 |
| 按下 | 手指按下 | **≤300ms 防误触**（不足时长松手=无效，不出结果），**底部绿色圆顶弹性升起**（全屏宽、约 1/5 屏高），中央白色麦克风图标，圆顶上方提示"松开跟读"，背景压暗 |
| 录音中 | 持续按住 | 圆顶内声波动画 + 已录秒数；圆顶上方提示换为"↑ 上滑取消" |
| 上滑取消 | 手指滑入取消区（阈值 ≥56dp） | 圆顶转红色取消态，提示"松开取消" |
| 松开（正常） | 按住 ≥300ms 且未滑入取消区 | 圆顶弹性收回（背景恢复亮度）→ loading（识别中）→ 结果上屏/记分 |
| 松开（取消区） | — | 直接丢弃，圆顶收回，无 loading，**不残留 partial** |
| 识别失败/空结果 | ASR Error/空 Final | 非阻塞提示"没听清，再试一次"，回空闲，不闪退 |
| 系统打断 | 来电/切后台 | 等价"取消"：停引擎、收圆顶、状态复位（补现有缺口） |

**时序约束（给工程师）**：Android SpeechRecognizer **无实时音量回调** → 声波是纯循环假动画（预置波纹 + 按住时长驱动节奏），不做音量映射、不承诺实时逐字上屏；partial 可预显但失败静默降级。**组件化**：通用组件（VoiceDomeOverlay，原 VoiceRecordBubble 更名），对话/课文跟读/单词跟读三页共用，禁止三份拷贝。

**不做**：真实音量波形、录音文件保存回放、按住超时上限（P2）。

## 需求 2：关卡奖励感升级（"学会 / 得到什么"）

**诊断**：引导页框架已有（NceRepeatScreen "通过本关卡，你将学会什么" group 卡），真实痛点是 ①objectives.json 目前是**占位数据**（tools/gen_placeholder_objectives.py 生成的"跟读并学会说：xxx"句式，且代码里还要 removePrefix 去壳），没说服力；②通关"得到什么"奖励感弱。

### 三段循环（具体文案 + 触发时机）

| 阶段 | 现状 | 升级（文案示例 / 触发时机） |
|------|------|------------------------|
| 进关前（期待） | 占位 objectives | ①**跑 LLM 预生成替换 objectives.json**（P0 根因，接口不变）：每课 2~4 条"学会什么"句式，如"学完这关，你可以用英语介绍你的家人，并听懂别人问'你家有几口人'"；②引导页底部加一行"通关可得：⭐成绩单 · 解锁下一关 · 徽章进度"，进关即见 |
| 闯关中（进度） | 句进度条（N/M 句） | 句进度旁加动态小字，触发时机=剩最后 2 句时："还差 2 句就通关，冲！" |
| 通关后（获得物） | 成绩单：总分/星级/评语/你学会了打勾（均已实现） | **里程碑徽章**：累计通关 10/50/100/276 关各一枚（共 4 档），触发时机=达到里程碑的当次成绩单底部插入一枚徽章卡："🎉 第 10 关达成！铜级徽章点亮"，平时在"我的"统计页展示"距下一枚还差 N 关"；best score 刷新时成绩单 caption 加"最高分刷新！88 → 93"（LevelProgressStore.recordScore 已存 best，只差展示） |

**获得物深度拍板：做到里程碑徽章为止，不做积分经济**。金币/商城/角色养成/勋章墙页面/经验等级全部不做——自用 + 10 分钟/天，奖励的价值是"感觉在积累"，4 枚徽章 + 已有星级 + 解锁动效就是合适深度，做重了变第二份负担。

**不做**：积分体系、养成系统、独立徽章页、周/月挑战。
**优先级/工作量**：预生成 P0（0.5 天脚本）；闯关中小字 + 通关可得行 P1（0.5 天）；徽章 P1（1 天，StatsStore/LevelProgressStore 加累计 cleared 数即可）。

## 需求 3：关卡卡片 AI 生成 SVG 插画

| 维度 | 拍板 |
|------|------|
| 结论 | **离线批量预生成 276 张（方案 A）**：开发期统一 prompt 模板（参数只有课文名场景描述）批量生成 → 人工抽查 ≥10% → 打包 assets；运行时零联网、零等待、零 token。运行时实时生成否决（慢、费 token、风格不稳、失败无兜底） |
| 使用位置 | 关卡卡背景装饰层（聚焦卡 + 关卡目录行缩略图标复用同一张）；不替换 Wallet 渐变，插画叠加在渐变之上 |
| 风格标准 | 白色单色 duotone（与现有 glyph 同语言放大）、几何简约线面结合、**无文字**、构图主体偏右上、左下白字区（场景名/状态/星级）构图留空；插画层透明度 ≤35% 且置于 sheen 反光层之下；锁定关 saturate(0) 规则不变——对比度靠构图约束保证，不靠算法兜底 |
| 命名规范 | `assets/nce/art/nce_{no}.svg`（如 nce_12.svg）+ 映射文件随 index.json 走；缺文件 = 自动回退现有 glyph，**绝不空窗、不需改代码** |
| 兜底 | 生成失败/抽查不达标 → 删文件即回退 glyph；首批可只做前 50 关灰度验证风格，再批量跑完 276 |
| 版权 | AI 生成原创，无碍 |

**不做**：运行时生成、动效插画、成绩单/课程页插画复用（先关卡卡验证效果再扩散）。
**优先级/工作量**：P1，流水线 + Compose 接入 1.5 天（AI 生成时间另计，建议与需求 2 的知识点预生成同一批离线跑）。

## 需求 4：口语生词点击释义（词卡）

**现状代码事实**：NceRepeatScreen 的 `WordTapText` 点词 = 直接 `addToVocab`（一步直收，`NotableWord(word)` 只带词、不带音标释义）；`VocabStore.add()` 已支持 phonetic/meaning/example 字段但**没被填**；VocabStore 有 `contains()` 去重。

### 口径（拍板）

- **交互统一：点词 = 弹词卡（一步）；收词 = 词卡内按钮（两步）**。WordTapText 的直收交互废弃改弹卡——否则"查释义"和"收词"两个意图挤在同一个点击上必然打架。弹层为底部词卡：词 + 音标 + 🔊发音（复用现有缓存/预加载/增益链路）+ 释义 + 一句例句 + 【＋收进单词本】。
- **收词复用 VocabStore，不新建收藏机制**：词卡收词时把音标/释义/例句一并传入 `NotableWord`（顺带修复"收的词没有释义"的现状缺陷），`sourceScenarioId` 仍传 `"nce_l{no}"`，1/3/7 复习与来源徽标全部自动继承；`contains()` 去重不变，已在词本的词词卡按钮显示"已在单词本"。
- **双通道并存、来源徽标区分**：notable_words 自动收集（对话纠错，标签"对话"）不变；用户主动查询后收藏（标签"NCE L12"）不变。自动收集解决"该记的词"，词卡解决"我不懂这个词"。
- **查询实现**：内置迷你词典（高频口语词 ~5000 条离线 JSON，秒开）→ 未命中走 LLM 单词查询（词/音标/释义/例句）→ 结果本地缓存（同词二次点击零成本）。
- **范围**：跟读页先行（276 关主玩法），对话页同组件紧随接入（可拆为 4b）；不做整句点选翻译（已有整句翻译按钮）、不做词形还原完备性（LLM 兜底）、不做全量离线大词典。

**优先级/工作量**：P1；词卡组件 + 迷你词典 1.5 天，LLM 查询 + 缓存 0.5 天，对话页接入 0.5 天 ≈ 2.5 天。
