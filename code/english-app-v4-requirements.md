# 需求方案 v4（PM 口径稿 · 真机 v9-dome 包四条反馈 · 基于 EnglishCoach 现状代码）

> 代码基线：NceScorer.kt（打分 + ReviewFeedback 接口 + LocalTemplateReviewFeedback）、VocabularyScreen.kt（词本列表/复习）、StatsScreen.kt（streak/累计/徽章/日历）、NceRepeatScreen.kt（跳过入口在 L790"跳过这句 →"）。
> 原则不变：自用、碎片 10 分钟，每条明确"不做什么"。

## 需求 A：AI 教练——每关的学习诊断与改进建议（重点）

**拍板结论：做"通关后成绩单页的 AI 诊断卡"，一次通关一次调用；接口复用现有 ReviewFeedback，LocalTemplateReviewFeedback 保留为兜底，是升级不是并存两套。**

### 具体口径

| 维度 | 拍板 |
|------|------|
| 触发时机 | **通关后成绩单页**（finishLesson 出报告时），一次通关一次调用。**不做每句即时诊断**——每句调 LLM = 延迟 + 成本 ×N，且打断"听→跟读→下一句"的节奏；句级问题放进成绩单的"逐句诊断"里定位，效果等价 |
| 输入数据 | 每句 {原句英文, ASR 识别文本, similarity, fluency, completed} + 全课 accuracy/completeness/fluency/total/stars。**注意数据缺口**：NceSentenceScore 目前不含 recognized 文本，需把识别文本带进报告（NceScorer.score 里补字段，改动小） |
| 输出结构 | 固定 JSON：① 总评 1 句（鼓励，进步教练口吻）② 逐句诊断：只挑 **最多 2~3 个最值得改的句**，每句 = 问题定位（漏读/读错哪个词）+ 具体改进建议（怎么读/注意什么）③ 行动引导 1 句。不逐句流水账——276 关 × 每课 10 句，全量诊断浪费 token 且用户看不完 |
| 成本控制 | 一课一次调用，估算 in 500~800 / out 300 token ≈ 每次 ¥0.002 量级，每天几课 = 每月几块钱，可接受。**缓存**：同 levelKey + 相同 attempts 指纹（total+完成句数+识别文本 hash）不重复调用，重练且成绩变化才重新生成 |
| 兜底 | LLM 失败/无 Key → **降级到现有 LocalTemplateReviewFeedback**，成绩单永不为空。诊断卡 UI 两态：AI 卡（带"AI 教练"角标）/ 模板卡，用户无感切换 |
| 与现有模板关系 | **升级**：ReviewFeedback 接口不动（或加一个 diagnose 可选方法），新增 LlmReviewFeedback 实现类，NceScorer/展示层按"LLM 优先、模板兜底"取数。LocalTemplateReviewFeedback 不删除 |
| 展示位置 | 成绩单 AI 评语卡升级为"AI 教练诊断卡"：总评 + 逐句问题（句号 + 原句节选 + 一句建议），替换现在只有 2~3 行的 commentLines |

**不做什么**：每句即时流式诊断、语音版教练反馈（TTS 读建议，P2）、跨课学习计划生成、发音口型/音素级分析（ASR 文本相似度做不到，不承诺）。
**优先级**：P0（用户点名"重点"）。**改动量**：2~2.5 天（数据补字段 + LLM 实现 + 缓存 + 成绩单卡改版）。

## 需求 B：单词页"没有数据 + UI 不好看"

**拍板结论：先修"数据贫瘠"（根因），再重做列表卡与空态——两者是一件事：现在收的词没有音标释义，自然显得又空又丑。**

### 诊断（基于代码）

1. **收词链路本身没坏，但量必然少**：notable_words 自动收集只在**对话页**产生，而纯 NCE 轨道下用户几乎不进对话页；NCE 收词靠跟读页手动点词——用户没点过就是 0。
2. **已收的词质量差**：NceRepeatScreen.addToVocab 只传 `NotableWord(word)`，音标/释义/例句全空 → 列表行只有单词没有内容，"不好看"的实质是数据贫瘠。

### 具体口径

| 项 | 口径 |
|----|------|
| 收词带全量字段 | 跟读页点词 → 词卡（v3 需求 4 已上线）→ 收词时把词典/LLM 查到的音标、释义、例句一并传入 NotableWord 入库；NceRepeatScreen 旧的一步直收路径确认已废弃 |
| 旧数据补全 | 列表里无释义的旧词显示"点此补释义"→ 调 LLM 补全并回写 VocabStore（一次一词，量小成本可忽略） |
| 有词列表卡 | 每行 = 词（大字）+ 音标 + 中文释义（一行截断）+ 来源徽标（NCE L12/对话）+ 复习状态点（未到期灰/今日到期橙/已毕业绿勾）；点击展开复习入口 |
| 复习卡置顶 | 今日到期词 > 0 时，顶部"今日复习 N 个"卡置顶（逻辑已有，确保视觉第一优先） |
| 空态引导 | 无词时给三步引导卡：①跟读时点句子里的词 → ②弹出词卡看释义 → ③点"收进单词本"。配一张示意小图，明确"词从哪来" |

**不做什么**：批量导入/导出、整页词典浏览、自动收集开关（量少的问题靠引导解决，不是放开自动灌水）。
**优先级**：P0（用户明确不满）。**改动量**：1.5~2 天（词卡字段回写 + 列表卡改版 + 空态 + 补释义）。

## 需求 C：统计页数据价值评估与取舍

**拍板结论：砍"累计对话轮数"（纯 NCE 轨道下口径已失义），改"累计跟读句数"；新增"本周"视角和"最弱句回顾"；其余保留。**

### 逐项取舍清单（诚实评估：对"10 分钟/天自用、鼓励式"目标的价值）

| 现有数据 | 判断 | 理由 |
|---------|------|------|
| 连续打卡天数（streak 卡） | ✅ 保留 | 督促核心，防放弃支柱，不动 |
| 累计开口分钟 | ✅ 保留 | 直接对应 3 分钟保底目标 |
| **累计对话轮数** | ❌ **砍掉** | 场景关移除后用户主要在跟读，"对话轮"概念已失义，数字还会误导 |
| 打卡天数（累计） | ⚠️ 合并 | 与 streak 卡副标题重复，并入打卡卡一行"累计 X 天" |
| 里程碑徽章进度 | ✅ 保留 | 2b 刚做的激励，有用 |
| 月打卡日历 | ✅ 保留 | 留存可视化，低成本 |

### 替代/新增数据

| 新数据 | 口径 | 价值 |
|--------|------|------|
| **累计跟读句数** | 替代对话轮数（DailyRecord 加 readSentenceCount，跟读 Final 时 +1） | 真实反映"说了多少"，数字会持续涨，鼓励感强 |
| **本周卡** | 本周开口分钟 + 本周通关关数（从 records 按周聚合，零新存储） | "这周练得怎么样"比"累计"更有行动意义，10 分钟/天的人看周不看总 |
| **最弱句回顾** | 持久化最近成绩单的逐句得分（NceScorer 已产出 sentenceScores，只存最近 10 课），列相似度最低的 3 句 + 原句 + 一键进该课重读 | 把"诊断"（需求 A）沉淀成"行动"，统计页从"看数字"变"有下一步" |

**不做什么**：图表化（曲线/柱状图，P1 再说）、与其他 App 对比、目标设定系统。
**优先级**：P1。**改动量**：1.5 天（砍 1 项 + 加 3 项，其中最弱句需新增最近报告存储）。

## 需求 D：关卡页底部布局 + 圆顶浮层 + 移除跳过

### D1. 底部布局优化

**拍板结论：把底部散块整合为一条固定"控制舱"：一行并排 [▶ 原声] + [按住 跟读]，状态文案集成进舱内。**

现状问题（截图 + 代码）：播放圆钮 + "原声播放中…"文字、灰色禁用胶囊、三块各自居中，层次散；PLAYING 阶段胶囊灰禁但无任何说明（用户当 Bug）。

| 项 | 口径 |
|----|------|
| 布局 | 底部固定区（白色/毛玻璃背景、上圆角）内一行：左 [▶ 46dp 圆钮] + 右 [按住 跟读 胶囊，等高]，间距 12dp，整体居中；当前句状态（"原声播放中…/请跟读"）作为舱内顶部一行 12sp 小字，不再独立漂浮 |
| 禁用态 | PLAYING 阶段胶囊保持灰禁，但舱顶状态行必须写"先听原声，听完就能跟读"——禁用必须带解释 |
| 层次原则 | 一屏三段：句子大卡（学什么）→ 控制舱（怎么操作）→ 圆顶（录的时候）。中间不要游离元素 |

### D2. 圆顶录音浮层修正

**拍板结论：先按下面清单逐项排查实测问题，统一修正后再交付；不做推翻重来。**

| 可能问题点 | 修正口径 |
|-----------|---------|
| 升起动画生硬 | spring 弹性曲线（dampingRatio ~0.75），升起 250~300ms，收回 200ms；禁止线性/瞬现 |
| 高度占比不对 | 固定约 1/5 屏高（含提示行），小屏（≤6.7"）不低于 140dp、不大屏超过 200dp |
| 提示文案/状态不齐 | 按状态机核对：按下即出"松开跟读"、录音中"↑ 上滑取消"、滑入取消区"松开取消"（红）、时长秒数随录音跳动 |
| 与底部按钮关系 | 圆顶 z 序在控制舱之上、背景压暗舱体；圆顶升起时舱内胶囊同步变"录音中"实色，避免两个视觉焦点 |
| 声波/秒数假动画 | 维持口径：纯循环动画 + 按住时长驱动秒数，无音量联动 |
| 取消后按钮态 | 取消/失败后胶囊回"按住 跟读"原样，不残留录音色 |

### D3. 移除跳过功能

**拍板结论：关卡内**所有跳句入口全部移除，口径 = "每句必须跟读完成才能进下一句/通关"。**

- 删除 NceRepeatScreen L790"跳过这句 →"入口与 `skipSentence()`；与既有 P1-1 防跳关（全跳不出通关记录）形成完整闭环：没有跳过路径 → 防跳关自然恒成立。
- 边缘口径：某句连续 3 次 ASR Error → 出"这句再试一次"提示（换提示不换机制），**不提供跳过**；坏句文件（lrc 解析为空）属加载失败走既有"课文加载失败，请返回重试"路径，不属于跳句。
- **复习页"跳过这个词"保留**——那是复习顺延机制（不惩罚口径），与关卡跟读是两回事，明确区分避免误伤。

**优先级/改动量**：D1+D2+D3 合计 P0（用户真机直接不满），1.5~2 天。
