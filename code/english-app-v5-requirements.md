# 需求方案 v5：单词分段点击发音（PM 澄清 + 口径稿 · 工程师可直接照做）

> 用户原话（语音转写）："一个单词是有多个部分组成的，我希望在学习单词时可以根据不同的部分去点击，然后发音。"
> 代码基线：DictStore.kt（dict.json 三级词典）、SiliconFlowTtsClient.kt（CosyVoice2 + SHA-256 磁盘缓存 + 预加载/在途去重 + ratePercent 调速）、WordRepeatScreen.kt（单词跟读堆叠卡）、词卡弹层（v3 需求 4）。
> 目的判断：用户要的是**学发音、帮记忆**——分段点击 = 让用户看清"这个词由哪几块音组成、哪块要重读"，不是语言学分析。

---

## 澄清点 1："部分"的定义 —— 拍板：音节（P0），词根词缀不做

| 候选 | 评估 | 结论 |
|------|------|------|
| ①音节（fam·i·ly） | 最通用：每个多音节词都有；直接服务发音（一拍一块）和拼写记忆；数据可批量生成 | ✅ **P0 做** |
| ②自然拼读单元（ph/ch/tion） | 与音节大量重叠，独立成层反而增加点击噪音；重音标注已覆盖主要价值 | ❌ 不单独做 |
| ③词根词缀（un·happi·ness） | 对"发音"帮助间接（词缀影响的是语义记忆）；数据成本高且规则多例外 | ❌ 不做（P2 远期若做记忆功能再议，数据结构预留 `morph` 字段即可） |

**单音节词**（如 "go"、"big"）无需分段：直接显示整词 + 整词发音，不渲染分段区。

---

## 澄清点 2：拆分数据来源 —— 拍板：离线预生成 JSON（方案 A），不做运行时 LLM

| 方案 | 评估 | 结论 |
|------|------|------|
| A. 离线批量预生成 | 与 objectives.json 同套路：智谱批量跑一次 → 静态 JSON 进 assets，运行时零成本零延迟；质量可控（脚本校验） | ✅ **做** |
| B. 运行时 LLM 拆 | 进词卡多一次网络请求（1~3s），且拆分不稳定、拆错会**误导发音**——比没有更糟 | ❌ 否决 |
| C. 本地启发式算法 | 元音组切分规则例外多（-tion/-ious/成音节 l），不可靠 | ❌ 否决 |

### 数据规格（工程师照做）

- **词表范围**：`assets/nce/dict.json` 全部词（内置迷你词典）+ `words.json` 48 词（单词跟读内置词）+ VocabStore 已收录词的导出快照。预计 1000~2000 词，一次跑完。
- **文件**：`assets/nce/syllables.json`，格式：
  ```json
  {
    "family": { "s": ["fam", "i", "ly"], "st": 1 },
    "excuse": { "s": ["ex", "cuse"], "st": 1 }
  }
  ```
  `s` = 音节数组（全小写）；`st` = 主重音音节下标（0-based）。只标主重音，不标次重音（简化）。
- **生成脚本**：`tools/gen_syllables.py`（参照 gen_lesson_svgs.py / gen_placeholder_objectives.py 模式）：智谱批量 prompt → 逐词校验 **`"".join(s) == word（全小写）`** 且 st 在下标范围内，校验失败丢弃该词条（宁缺勿错）。预计每千词一次批量跑。
- **词表外的词（降级策略）**：词卡只显示整词 + 发音按钮 + 一行灰字"分段暂不支持"，**不做运行时补拆**。新词随下次离线批量跑补进 JSON。

### 加载层（新增 SyllableStore）

- 仿 DictStore：启动不加载，首次访问懒加载 + 内存缓存；`lookup(word): Syllables?`，查不到返回 null（UI 走降级）。

## 澄清点 3：每段怎么发音 —— 拍板：逐段直送 TTS 为主（需真机试听验证），整词慢读为必备兜底

| 方案 | 评估 | 结论 |
|------|------|------|
| ①逐段直接送 TTS | CosyVoice2 是整句 TTS，单音节（"cuse"、"ly"）不是合法词，**发音质量存疑**——可能怪异/拖长 | ✅ 主方案，**前提：真机试听通过**（见验收标准） |
| ②伪词/连字符引导停顿 | CosyVoice2 无 SSML 保证，连字符行为不可控，等于赌 API 内部实现 | ❌ 否决（不作方案，试听阶段可顺带试，不写进产品） |
| ③整词慢速朗读 | ratePercent 调速（speed 0.25~4.0 已支持，取 0.6~0.7）最可靠，但"分段"的用户诉求没满足 | ✅ **必备兜底 + 独立按钮**（"整词慢读"） |

**真机试听验收标准（实现前先做一个 5 词试听 Demo，工程师半天）**：取 family / excuse / important / comfortable / reasonable 各音节逐段播，标准 = 每段**可辨识、无怪异拖长/杂音**。通过率 <80% → 主方案降级为"整词慢读 + 重音音节高亮提示（不发音）"，**此决策点在工单中显式保留**。

**缓存与成本**：音节合成天然复用现有链路——磁盘缓存 key=`text|voice|speed`（音节文本极短、命中率极高）、预加载（进词卡时后台预载该词全部音节 + 整词慢读共 N+1 条）、在途去重已有。成本：单次请求几十字符，月成本忽略不计。

## 澄清点 4：交互设计 —— 生效页面与交互规格

**生效页面（拍板）**：

| 页面 | 范围 | 说明 |
|------|------|------|
| 词卡弹层 | **P0** | 点词释义词卡（全 app 通用：NCE 跟读页点词、对话页点词都弹它）——改一处，全 app 生效 |
| 单词跟读页（WordRepeatScreen 堆叠卡） | **P0** | 学单词主场景，单词大字直接按分段渲染 |

### 交互规格（给 UI + 工程师）

- **分段渲染**：音节之间 4~6dp 间隔（或细分隔点），重音音节加粗 + 主题色（HyperBlue），非重音 TextPrimary；
- **点击**：点某段 → 播该段音（按钮级 loading，复用现有在途去重；连续点不同段直接切播，不排队）；
- **按钮组**：分段区下方两个 pill——【整词慢读】（speed 0.65）与【分段连读】（依次播各音节，间隔约 150ms，播完自动停；连读中再点=中止）；
- **降级态**：词表外词——整词渲染 + 常速发音按钮 + 整词慢读按钮 + 灰字"分段暂不支持"；
- **单音节词**：整词渲染 + 常速/慢读两按钮，无分段区。

**不做**：NceRepeatScreen 句子大卡的词级改造（点词仍弹词卡，词卡内已有分段能力，零改动获得）。

---

## 不做什么（边界）

- ❌ 音标级 phoneme 发音（音素级合成，TTS 做不到，不承诺）
- ❌ 每段录音对比打分（跟读打分是句级口径，段级音频比对是另一个产品）
- ❌ 词根词缀层（数据结构预留，功能不做）
- ❌ 运行时 LLM 拆分 / 词表外自动补拆（只降级）
- ❌ 次重音标注、英式音（CosyVoice2 现有音色即口径）
